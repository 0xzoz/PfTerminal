# Issue912: billed warm-up with no saved turns

Class: bounded presentation fix for the accepted developer-only `/cost` flow, following maintainer issue912 and the existing #403 reopen-warm-up display. Product link: **Product measurement**, excerpt “No commercial performance numbers have been supplied.” The existing PF-60 accounting follow-up intent is that every paid request has a label saying what it was and is shown without misleading figures. This patch adds no pricing, settlement, routing, schema, persistence, security or financial authorization change, and creates no product initiative or release.

A billed request can exist without a saved turn that `/resume` can discover. The other-conversation cost view previously told the user to resume that conversation unconditionally. The current warm-up display named the charge without explaining this exception. Cost is still recorded even when the conversation has no saved turns.

The fix adds one shared conditional explanation wherever reopen warm-up requests are present, and qualifies the other-conversation resume advice. It deliberately says “a conversation with only a reopen warm-up and no saved turns”; a date-limited accounting view cannot establish that an existing conversation has no older turns. Normal requests receive no warm-up note. Recorded attempts, totals, prices, stored data and resume code are unchanged.
