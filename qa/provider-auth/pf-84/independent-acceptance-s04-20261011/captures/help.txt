Add or replace a named account. Secret values are read from stdin

Usage: corbanu account add [OPTIONS] <PROVIDER> <NAME>

Arguments:
  <PROVIDER>
          Provider id, for example `zai` or `claude-plan`

  <NAME>
          Account name: 1-32 lowercase letters, digits or '-'

Options:
  -c, --config <key=value>
          Override a configuration value that would otherwise be loaded from
          `~/.corbanu/config.toml`. Use a dotted path (`foo.bar.baz`) to override nested values. The
          `value` portion is parsed as TOML. If it fails to parse as TOML, the raw string is used as
          a literal.

          Examples: - `-c model="o3"` - `-c 'sandbox_permissions=["disk-full-read-access"]'` - `-c
          shell_environment_policy.inherit=all`

      --kind <KIND>
          What the account holds

          Possible values:
          - api-key:           A provider API key (stdin)
          - claude-token:      A Claude subscription token from `claude setup-token` (stdin)
          - claude-config-dir: The `CLAUDE_CONFIG_DIR` of a Claude Code login (`--value`)
          - command:           An account of an `auth.command` provider; the command receives its
            name in `CORBANU_PROVIDER_ACCOUNT`

          [default: api-key]

      --enable <FEATURE>
          Enable a feature (repeatable). Equivalent to `-c features.<name>=true`

      --value <VALUE>
          The value for the non-secret `claude-config-dir` kind

      --disable <FEATURE>
          Disable a feature (repeatable). Equivalent to `-c features.<name>=false`

  -h, --help
          Print help (see a summary with '-h')
