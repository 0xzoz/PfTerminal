[P1] Second 401 on an already-rejected provider silently clears the recorded credential failure
codex-rs/provider-auth/src/credential_health.rs:63
`ProviderStatusHost::begin_credential_attempt` captures the status via `resolve_provider()`, which runs `ProviderCredentialHealth::apply`. After a provider has been rejected once, the captured `Attempt.methods` for the next turn are already `RecoveryRequired { CredentialRejected }`. Chat submission is not gated on provider health, so a user who sends another message (or any new turn arriving) with the same rejected credential gets a second typed 401; `reject()` then overwrites `rejected[provider]` with the attempt whose methods are `RecoveryRequired`. On the next `apply`, `rejected.methods != status.methods` (fresh statuses are `Configured`) so the entry is skipped and the provider flips back to `Enabled · configured` while the TUI simultaneously prints "A provider credential was rejected". This violates the boundary requirement that a failure persists until a matching credential replacement (revision bump) occurs. None of the new unit or tmux tests exercise two consecutive rejections without recovery. Smallest fix: keep the existing entry (`self.rejected.entry(provider).or_insert(attempt)`), or have `begin` skip/normalize when the captured status is already a `CredentialRejected` recovery state.

overall: patch is incorrect (0.8)
The typed 401 attribution (rmcp-client → codex-mcp → protocol), the source-aware recovery view, the API-key cancel plumbing, and the eligibility/status changes are coherent and consumers still gate on availability. However, the session-local health ledger has a concrete defect: because attempts are captured from an already-applied status, a repeated rejection of the same credential overwrites the ledger with mismatching methods and clears the failure, contradicting the 'failure retained until matching replacement' contract. Additionally the new snapshot test references a narrow snapshot that is not committed, so the advertised unit gate will fail as-is.
