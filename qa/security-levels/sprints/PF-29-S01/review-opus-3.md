VERDICT: Conditional pass. The nested-agent toggle can't save Aggressive while preflight blockers exist, but the new database glob leaves a gap on Linux, so I found no P0/P1 and three P2s that should be fixed.

**Toggling nested agents on a saved Aggressive.** The preflight is skipped only when the stored level is already Aggressive. Moving from Permissive or no saved level still runs the preflight, and a blocked review still hides the save action and refuses to save. On a failed save, the receipt is now removed only when this save wrote it, so a receipt from an earlier preflight is no longer deleted. That is correct.

**P2. Picker uses the level it read when it opened.** `bottom_pane/security_level_picker.rs:200` (`preflight_allows_save`) and `:236` (`save`) rely on `self.stored` from when the picker opened. Suppose another Corbanu process saves Permissive while this review is open, which also deletes the receipt. Pressing `n` and Enter then writes Aggressive with no receipt. At launch, `isolation_paths` (`security/preflight.rs:166`) returns nothing when there is no receipt, so Aggressive starts with none of the extra read denials. An agent can't cause this, because the profile makes the home read-only. Fix: reload `level::load_state` inside `save`, and skip the preflight only if the stored level is still Aggressive and `preflight::receipt_path(..).exists()`. Otherwise, run the preflight.

**P2. On Linux, the glob is expanded only to files that already exist.** `core/src/security/preflight.rs:281` (`database_glob`) and `tui/src/security/preflight.rs:176` drop the per-file database denials in favour of `<home>/*.sqlite*`. Bubblewrap masks only the files that exist when a command starts (`linux-sandbox/src/bwrap.rs:430-436`). So a `-wal`/`-shm` file created during a long agent command is readable from inside it, which is the same race the GLM run found, now on Linux only. macOS Seatbelt evaluates the pattern on each read and is not affected. Meanwhile `verify_isolation` reports the databases as denied because the glob string is in the policy. Fix: on Linux, also deny the database directory or move the state databases into a denied subdirectory such as `<home>/state/`. Failing that, say in the Linux review text that it isn't covered.

**P2. Glob characters in the home path.** `database_glob` builds the pattern with an unescaped `codex_home.join("*.sqlite*")`. If the home path contains `[`, `]`, `?`, `*` or `{`, the pattern won't match the real files. `verify_isolation` (`tui/src/security/preflight.rs:193-208`) compares the strings exactly, so it still passes while the databases stay readable. Fix: escape glob characters in the home path, or refuse Aggressive at launch when the path contains them. Also add a test with a home such as `a[1]`.

**P3. Missing-store denials on Linux.** `CORBANU_HOME_STORES` (`core/src/security/preflight.rs:267`) is denied before the stores exist. A store created later in the session may not be masked by bubblewrap for commands that started earlier. The risk is low, because the home is read-only and each new command gets fresh mounts. Fix: create the store directories (`sessions`, `archived_sessions`, `shell_snapshots`, `log`, `wallet`) at launch, the same way `secrets` is created now.

**P3. Path checks use the exact home path.** `is_database_file` and the receipt checks compare `parent() == codex_home` literally. If `config.codex_home` and the inventory's home differ (for example `/var` versus `/private/var` on macOS), the check fails closed: Aggressive refuses to start rather than leaving files readable. This is safe, but it may give false launch failures. Fix: canonicalize both paths.

No regressions found otherwise:
- **Receipt version 2:** a version-1 receipt can't be parsed, so it can't make old conversations look new. Because launch only checks that the file exists, a version-1 receipt still turns on the extra denials.
- **Database files:** a renamed or new database directly in the home still falls under the glob, apart from the Linux timing issue above.
