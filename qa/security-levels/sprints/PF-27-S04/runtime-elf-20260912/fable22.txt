[P3] External-loader tag denial test cannot distinguish vocabulary rejection from missing DT_NULL
codex-rs/secret-broker-service/src/launch/manifest/elf_tests.rs:122
In `pf_27_s01_elf_profile_dynamic_vocabulary_and_termination`, the first loop writes the external/unknown tag (DT_NEEDED, RPATH, RUNPATH, FILTER, AUXILIARY, AUDIT, DEPAUDIT, 0xdead) at offset 400 while the fixture's PT_DYNAMIC size remains 32 bytes (two entries). That leaves the table with no DT_NULL terminator, so `inspect` would deny even a fully supported tag via `require(terminated && pie)`. The assertion therefore passes for the wrong reason and does not prove the contract's "each external-loader tag denied independently" row. The duplicate-FLAGS_1 case (`put(400, 0x6ffffffb)`) has the same shape. The later supported-tag loop already shows the correct pattern (size 48 with a trailing zero entry); apply that to these cases so the vocabulary match arm is what is actually exercised.
