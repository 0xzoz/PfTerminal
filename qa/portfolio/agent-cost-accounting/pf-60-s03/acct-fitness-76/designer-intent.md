# Developer usage-inspection intent

A developer deliberately enables usage recording in a development build and
wants to explain displayed estimates using constituent requests and attempts,
without opening storage. They choose UTC days or ranges and grouping intervals,
inspect their session and related agents, navigate details, and return to work.
They need to understand what the displayed amounts cover and what is unknown.

Recording is developer-only and opt-in; it must remain unreachable in shipped
builds. Inspection is read-only. Reported usage and estimated dollars are distinct
from settled bills. Missing evidence must remain missing. Profiles and service
responses used for testing are synthetic; no personal credentials or live money.

Propose independent prioritized cases with starting state, actions and observable
results. Include questions about ambiguous intent. This input specifies no
expected test count and supplies no implementation, prior tests or verdicts.
