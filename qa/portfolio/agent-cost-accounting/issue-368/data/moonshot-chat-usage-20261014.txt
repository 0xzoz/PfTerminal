Source: https://platform.kimi.ai/docs/api/chat.md (Chat Completions reference, "Context Caching (Cache Write)" section),
fetched 2026-10-14 ~23:10Z with curl. Recorded facts (paraphrased; see the page for the text):

- Context caching is automatic. `prompt_cache_options` controls writes; when it is omitted, writes use the 5m tier.
  `prompt_cache_options.ttl` accepts "5m" (default) or "1h".
- Cache hits are billed at the cached-input price only; a hit refreshes the entry with no further write charge.
  Cache writes are billed by TTL (pricing page: K3 $3.00/M at 5m, $6.00/M at 1h).
- Usage fields: `usage.prompt_tokens` is all input tokens. `usage.prompt_tokens_details.cached_tokens` = cache read;
  `usage.prompt_tokens_details.cache_write_tokens` = cache write. Cached, written and the uncached rest are
  mutually exclusive and sum to `prompt_tokens`.
- Streaming: the breakdown arrives in the final chunk's `usage` with `stream_options.include_usage=true`.
  Chat Completions responses do not echo the applied TTL.
- Example final chunk on the page: {"prompt_tokens":19,"completion_tokens":13,"total_tokens":32,"cached_tokens":12,
  "prompt_tokens_details":{"cached_tokens":12,"cache_write_tokens":0}}

Corbanu's Chat Completions request body (codex-api ChatCompletionsRequest) has no `prompt_cache_options` field, so
every request it sends gets the 5m tier.
