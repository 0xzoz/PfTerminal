## Behavior and boundaries
`AuthorizationChanged(Vec<UserInput>)` returns the original input. The native `Op::UserInput` handler consumes it through `defer_user_input_until_active_turn_finished`. A separate deferred queue prevents regular-turn drains from consuming it. Natural completion submits the existing follow-up operation under fresh settings, preserving the client delivery ID. If completion wins the deferral race, `NoActiveTurn(items)` starts a freshly derived turn. Nonempty input cannot reach the helper's remaining `EmptyInput` error arm. Interruption transfers deferred input to session storage for the next admitted turn.
Mail admission and extension injection now compare authorization while holding the active-turn and settings locks. Deferred mail retains its parent provenance and excluded turn ID; ordinary draining and pending-work checks exclude it for that turn even if settings revert or delivery reopens. A completed/aborted boundary permits subsequent delivery. Extension response items stay out of history during the running turn; normal completion records them for future turns (response-only injection does not itself start a new model turn). Interruption retains them for the next admitted turn.
The comparison reads only session approval policy, canonical permission profile materialized with primary workspace roots, approval reviewer and Windows sandbox level. It never builds or compares an entire Config. Model, reasoning, MCP configuration, user-layer provenance and other runtime-reload fields cannot perturb these fields.
The exact-turn JSON-RPC `turn/steer` API still rejects admission to the old turn rather than claiming a future turn fulfilled `expectedTurnId`. Its error data now contains `code: authorizationChanged`, `inputDisposition: returned` and the original input. The API client retains its request and can restore/queue it and submit after completion; there is no server-side acceptance or automatic retry on this API. Structured tracing records the boundary/disposition without input contents. Typed `CodexErrorInfo`/`AnalyticsJsonRpcError` variants require protocol/analytics paths outside scope; the typed analytics bucket remains absent, explicitly. This API limitation is distinct from automatic deferral of native `Op::UserInput`.
Brief corrections: the old check already compared four authorization fields, not whole-Config equality; the concrete user-layer reload counterexample was not established by that code. The existing deferral helper alone was insufficient for regular turns: its old pending queue was drainable by them. F04 remains untouched and is only a negative authority witness, not proof of new-turn execution.
