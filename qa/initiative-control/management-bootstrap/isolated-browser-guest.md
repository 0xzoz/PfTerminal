## Strict JSONL request contract

One request then one response; UTF-8 JSON object terminated by LF, ≤8192 bytes including LF. Duplicate/unknown keys, extra fields, bad types, nonfinite numbers and malformed UTF-8/JSON terminate the run. `seq` is a positive integer, strictly greater than every preceding accepted sequence, ≤9007199254740991; booleans are not numbers. No URLs, paths, selectors, evaluation, shell, configuration, uploads, downloads or callbacks are request fields.

| op | Exact fields besides `op` and `seq` | Meaning |
| --- | --- | --- |
| `observe` | none | Fresh bounded rendered-body text and viewport PNG |
| `click`, `hover` | `frame_id`, `x`, `y` | Finite viewport coordinates, 0≤x<width, 0≤y<height; primary click or pointer move |
| `text` | `frame_id`, `text` | Literal Unicode string ≤4096 UTF-8 bytes, inserted without pressing any key |
| `key` | `frame_id`, `key` | One enumerated key below |
| `scroll` | `frame_id`, `dx`, `dy` | Finite wheel deltas: −width≤dx≤width, −height≤dy≤height |
| `back`, `reload` | `frame_id` | Browser history back or current-page reload |
| `finish` | none | End protocol; no acceptance verdict |

Keys: `Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, `ArrowUp`, `ArrowDown`, `ArrowLeft`, `ArrowRight`, `Home`, `End`, `PageUp`, `PageDown`, `Space`. Text containing a newline or the word Enter remains text. Every mutation requires the latest observation's exact `frame_id`, consumed before execution; observe again before another mutation. Freshness binds the last protocol snapshot, not a frozen DOM or atomic text/screenshot capture.
Example exchange: `{"seq":1,"op":"observe"}`, then `{"seq":2,"op":"text","frame_id":"run1:case1:1","text":"literal text"}`, then observe at3 and `{"seq":4,"op":"key","frame_id":"run1:case1:3","key":"Enter"}`, then `{"seq":5,"op":"finish"}`.

## Response and terminal contract

Observation: `{"seq":1,"run_id":"run1","case_id":"case1","status":"observed","frame_id":"run1:case1:1","text":"…","text_truncated":false,"png_base64":"…","url":"http://127.0.0.1:8768/index.html"}`. Text is rendered body text only, ≤16384 UTF-8 bytes, with explicit truncation. No DOM, selectors, source, console, network bodies or old findings are emitted. Screens are untrusted fixture content.
PNG: viewport only, ≤2MiB, exact profile dimensions, 8-bit RGB/RGBA, noninterlaced; signature, IHDR/IDAT/IEND ordering, lengths and CRCs checked. No ancillary chunks accepted. Guest relies on Chromium's encoder; parent transport independently validates bounded DEFLATE. Parent can decode `png_base64` into `execute(text, image_png=...)` without any guest-selected path. Supplied pixels do not attest model observation (`supplied_not_attested` remains parent-owned).
Mutation: `{"seq":2,"run_id":"run1","case_id":"case1","status":"executed","frame_id":null}` means only the browser call returned without a currently known violation. It is not UI success, settled navigation, successful submission, or case acceptance. Later browser failures remain failures; no retry or success receipt is emitted for an exception/known denial.
After cleanup, exactly one attempted terminal line: `{"status":"terminal","reason":"finish","phase":"protocol","run_id":"run1","case_id":"case1"}`. Other reasons: `eof` (incomplete), `error`, `timeout`; phase is `startup` or `protocol`. Errors add `error` and `error_truncated`; cleanup failure adds `cleanup_error` and `cleanup_error_truncated`. Error values preserve exception type/raw text prefix up to4096 characters. Keep these diagnostics owner-private; do not forward browser error call logs as model observations. No failed-request sequence is asserted; parent correlates retained raw input.
Packet failure emits `{"status":"terminal","reason":"packet_error","error":"…","error_truncated":false}` without unvalidated IDs. Exit0 requires explicit finish and clean shutdown; exit1 covers EOF, validation, timeout, browser or cleanup failure; exit2 means output failed and a complete terminal receipt cannot be assumed. A finish reason with `cleanup_error` is still failure.
All requests, including observe/finish, count toward40; the40th non-finish response is followed by action-budget failure. Packet load, partial-line completion, each action/observation, output write and cleanup each have5s bounds. Idle input uses the remaining300s run deadline; packet time counts against it. Cleanup and final receipt have at most5s each beyond that deadline. Each output line ≤3MiB; at most40 action responses plus one terminal (≤123MiB aggregate ceiling). Oversize/partial EOF/slow input fail without draining indefinitely; broken or stalled output cannot imply acknowledgment. Parent still owns the hard process-tree watchdog and reconciliation if cancellation/OS cleanup stalls.
