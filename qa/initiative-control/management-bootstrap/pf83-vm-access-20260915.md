# PF-83 executor VM: key authorisation and credential rotation

Travis provisioned a UTM virtual machine for the PF-83 code-blind functional
gate and supplied its address and account name in the private Slack channel.
The VM is reachable from this host (ICMP and an SSH banner; authentication
refused, as expected).

## 1. The supplied password is treated as exposed

The account password was posted as plaintext into the channel. The manager has
**not** stored it, echoed it, written it to any receipt, coordinator record or
log, and will **not** authenticate with it. Please rotate it.

Chat transcripts and channel history are not a credential store. Anything the
manager must actually use belongs in the encrypted vault and is fetched only at
the moment of use.

## 2. Authorise this public key instead

Then no secret is needed at all. On the VM, as the executor account:

```sh
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIHufGCvwJztJJmff70FhRuVGpyMwCAgDBgQcNVT6vCMf fable-pf83-gate@corbanu' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

The matching private key is held only in the manager's private run directory,
mode 0600, and is never committed or transmitted.

## 3. On the Docker suggestion

Docker on this host is simpler and is already what the DEC harness uses, so it
is a reasonable instinct. It was not chosen because PF-83 is the TUI
permission-confirmation path and the frozen gate requires the native macOS
matrix; a Linux container would yield useful partial evidence but could not
close PF-83-S01. If the provisioned guest turns out to be Linux rather than
macOS, that is worth knowing before any case runs, and the choice becomes
reduced-scope interim evidence versus a macOS guest.

## 4. What happens once access works

The environment preflight runs first. It checks filesystem, process and IPC,
network, Keychain denial, absence of any repository or source access, and
child-process confinement. It currently reports all **175 controls UNPROVEN**.
Cases execute only for controls it actually proves; anything unproven keeps its
cases `blocked`.
