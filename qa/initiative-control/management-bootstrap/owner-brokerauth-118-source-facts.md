- Stored format: `codex-rs/login/src/auth/storage.rs:39-62` defines optional `auth_mode`, `OPENAI_API_KEY`, `tokens`, and `last_refresh`. `codex-rs/login/src/token_data.rs:11-25` defines token fields `id_token`, `access_token`, `refresh_token`, `account_id`. Subscription bearer is **access_token**, not id_token (`codex-rs/login/src/auth/manager.rs:554-567`). Account header comes from **tokens.account_id** (`manager.rs:576-582`), not an inbound client account claim. `codex-rs/model-provider/src/bearer_auth_provider.rs:32-46` inserts Authorization, ChatGPT-Account-ID, and conditional X-OpenAI-Fedramp. - Base selection: `codex-rs/model-provider-info/src/lib.rs:80,1003-1022`: subscription defaults to `https://chatgpt.com/backend-api/codex`; API key defaults to `https://api.openai.com/v1`; explicit configured base URL overrides either. Thus broker ingress `/v1/responses[/compact]` can map to `/backend-api/codex/responses[/compact]` without product changes.
- Shared HTTP originator defaults to `codex_cli_rs`, overridden by `CODEX_INTERNAL_ORIGINATOR_OVERRIDE` or a supplied originator (`codex-rs/login/src/auth/default_client.rs:40-41,63-80`); default headers include originator and a constructed User-Agent (`default_client.rs:160-176,360-365`). Core can supply a thread originator override (`core/src/client.rs:2392-2396`). Forward the actual incoming originator/User-Agent, default originator only if absent; do not invent a pinned-client version/platform in User-Agent.
- Session headers: session-id and thread-id are derived from Responses metadata (`core/src/client.rs:2381-2409`; `codex-api/src/requests/headers.rs:5-13`). The Responses endpoint puts thread-id in x-client-request-id, and derives x-openai-subagent from session source (`endpoint/responses.rs:102-113`; `requests/headers.rs:16-32`). The broker continues to replace x-client-request-id with its attempt UUID and keeps client IDs separately. Optional compatibility/turn metadata comes from Responses metadata (`core/src/client.rs:1309-1323`); x-codex-beta-features from enabled session beta features and x-codex-turn-state from captured sticky routing state (`client.rs:5201-5224`). These are client-emitted conventions; source does not prove which are server-required. HTTP has **no unconditional OpenAI-Beta requirement**: the `responses_websockets=2026-02-06` header is a WebSocket handshake header (`client.rs:2261-2287`), outside this POST-only broker. Existing allowed optional headers can pass through. No Cookie is used by this bearer path.
- Expiration: `login/src/token_data.rs:117-135` decodes JWT `exp`. The server determines token lifetime; there is **no fixed access-token lifetime** established by this source. Proactive refresh is within five minutes of exp. If exp cannot be obtained, the client falls back to last_refresh older than eight days (`auth/manager.rs:227-228,3200-3223`). Eight days is a fallback refresh interval, not token TTL. Broker policy will be stricter: known future exp required, expired credentials refused.
- Refresh: client serializes refresh, guarded-reloads matching account state before refreshing (`auth/manager.rs:2991-3027`); 401 recovery reloads then refreshes (`manager.rs:2290-2338`). Refresh is JSON POST to `https://auth.openai.com/oauth/token` with client_id `app_EMoamEEZ73f0CkXaXp7hrann`, grant_type `refresh_token`, refresh_token (`manager.rs:237-240,1903-1942,2000-2027`). Source supports endpoint/client-ID overrides, which this bounded broker need not inherit from the environment. Successful optional replacement tokens are persisted and cache reloaded by the **client** (`manager.rs:1876-1898,3288-3308`). Expired/reused/revoked refresh tokens are permanent failures, with transient failures distinct (`manager.rs:1945-1971,3040-3080`). The read-only broker must keep rotation in memory only; restarting it cannot recover a rotated token absent external credential-file replacement. Never let its refresh writes race a live profile: it performs no file writes.
