## Implemented callable workflow

1. `decision_alerts.Store(private_root).initialize()` exclusively initializes an empty owner-private POSIX directory. Reopen with `Store(root)`; missing/corrupt files or lock are held, never initialized as empty. `alerts.json` and `replies.json` are separate checksummed, bounded files. `decisions.fixture.json` remains in its supplied private feed directory, managed only by unchanged `decisions.py`.
2. `enqueue(store, raw_feed, decision_id, remote, pinned_identity, allocation, now)` validates the whole feed and creates a stable immutable alert. `prepare(...)` exposes the same intent without writing. Identity fields are `team/channel/app/bot/generation/human`; allocation fields are `agent/allocation/running`. No credential value is accepted. The manager supplies the approved HTTPS dashboard origin. Parent summary and threaded question/context distinguish new/revised/resolved, retain revision/times, escape mentions/markup and use the existing `attention.document_url` published routes and decision anchor. The retained record/feed/payload digests bind the actual presented context; query values identify revision, not a new dashboard revision selector.
3. `send(store, alert_id, current_identity, exchange, cancelled=False)` consumes a stable parent attempt before exchange, saves the exact returned parent timestamp before the separate details attempt, and serializes competing processes. `exchange(request)` returns exactly `attempt/identity/payload_digest/thread_ts/ts`. `Rejected` means the adapter guarantees no remote acceptance. Exceptions/invalid receipts are uncertain, not sent; restart converts interrupted sending to uncertain. No retry loop exists. Cancellation persists; identity rotation holds remaining sends. `inspect` reports recovery state; `reconcile(store, alert_id, phase, evidence)` requires authenticated exact retained receipt evidence before any remaining pending phase can proceed.
4. `decision_replies.intake(store, alert_id, raw_bytes, verify)` calls an injected trusted verifier, with a 16 KiB input bound. The verifier must authenticate the original envelope before returning normalized event ID, pinned team/channel/human, thread/message/event timestamps, kind and sanitized text. An untrusted JSON boolean cannot establish verification. Durable event/message dedup precedes return; edits/deletes and out-of-order events remain inspectable, never replacing original reply text. Conflicting events require clarification. Reply text is data; receiving it neither resolves a decision nor dispatches work.
5. `snapshot(store, alert_id)` returns retained audit/processing state. `interpret(store, feed_root, event_id, manager, current_owner, now, checkpoint=...)` requires explicit manager `actor/answer/scope/alert/context_digest/audit/owner/interpretation`. Ordinary `answer` cannot accept ambiguity; `clarified-answer` explicitly addresses the complete pinned audit, while `clarify` holds it. Wrong context, resolved/revised questions and stopped/reallocated owners stay inspectable. An exact durable resolution intent is recorded before CAS, without altering the validated decision history.
6. `resume(store, feed_root, handoff_id, current_owner, now, checkpoint=...)` applies unchanged `decisions.save_fixture` append-only CAS and reloads after uncertainty. Exact retained target comparison recovers a saved resolution before the queue write, including later append-only feed advancement. Conflicts never overwrite a newer question; a saved answer is recoverable from its retained intent. Queue recovery does not authorize dispatch of subsequently changed context. These files are not one atomic transaction.
7. `dispatch(store, feed_root, handoff_id, current_owner, receive, now)` rechecks current owner, cancellation, audit and resolved context under store→existing feed locks, retained through request persistence, the bounded receiver exchange and durable receipt. `receive(request)` returns `handoff/owner/payload_digest/receipt_id`. The stable handoff/attempt is durable before exchange; uncertainty requires reconciliation, not another logical assignment. `reconcile_handoff(store, handoff_id, evidence, acknowledgment=None)` records delivery from exact authenticated receipt; only a matching actual `handoff/agent/allocation/payload_digest/receipt_id` acknowledgment marks `agent-acknowledged`. Received, needs-clarification, recorded, queued, delivered and agent-acknowledged are separate from transport pending/sending/sent/failed/uncertain.

Storage uses owner-only directories/files, no symlink/hardlink acceptance, bounded JSON with duplicate-key rejection, file fsync, atomic replace, directory fsync and a cooperating-process flock. No claim of exactly-once Slack delivery, cross-file atomicity, encrypted storage or survival of disk loss/hostile same-UID tampering. Pattern filtering cannot establish arbitrary prose is approved: callers supply approved sanitized context; trusted adapters must keep credentials/raw diagnostics outside these records. Lock ownership spans exchange; adapters must bound I/O, must not reenter this store, and must not write the held decision feed while their callback executes.
