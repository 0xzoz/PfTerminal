## Read first: a correction I got wrong

`MODEL-ECONOMICS-DATA.md` (commit `fe07f93f5`) lists plan-routed models with `—`
for cost. **That is wrong and it is the dangerous kind of wrong.** Plan is not
free. Verified 2026-07-26:

- Claude Fable 5 has no bucket of its own. On Max it draws the same weekly
  allowance as every other model, capped at 50% of it, and weighs roughly
  **2x an Opus session** against that pool.
- When the weekly window is exhausted, Claude does **not stop** — it overflows
  into prepaid usage credits billed at API rates ($10/M in, $50/M out) and
  charges the card automatically.
- Agentic subagent spawning multiplies this: one task branching into 4-6
  concurrent calls multiplies consumption. That is exactly what `/spawn` does.
  Reported cases of a 5-hour Max window gone in 8 minutes.

Consequence for this work: **`agents.provider_allowlist = ["claude-plan", ...]`
does not bound spend.** It bounds _which provider_ an agent may select. A
claude-plan agent that exhausts the weekly pool silently becomes metered on the
same provider ID, and the allowlist cannot see that. Do not tell the user that
config protects them from spend. It does not.

The correct mental model: plan = prepaid finite pool with silent overflow;
within the pool there is still a strong cost gradient (Fable ~2x Opus).
Fix `MODEL-ECONOMICS-DATA.md` before anyone builds allocation logic on it.

## Traps that cost me time — do not repeat

- `pgrep -f "cargo build ..."` **matches its own command line**. I reported
  "STILL BUILDING" for 24 minutes on a dead build. Use `pgrep -f "[c]argo"`.
- A lease test is **vacuous** unless the request exceeds 32,000 input tokens or
  128 KiB. My first "passing" proof ran at 8,358 tokens and proved nothing.
  Grow context first, then verify `last_input_tokens` in
  `provider_request_state`.
- There are **two** spawn chokepoints. `ensure_native_spawn_provider_ready` is
  TUI-only; model-driven `spawn_agent` goes through core
  (`multi_agents_common.rs`). A guard in one does not cover the other.
- Authorize **before** mutating config. My first core guard ran after
  `corrected_catalog_provider` had already reassigned the provider, so a
  refused switch left the child pointed at the unauthorized provider.
- Flipping `MultiAgentV2` `default_enabled: true` adds ~7 test failures on top
  of the 9 pre-existing. Tractable but not contained; I reverted it.
