## Required final coupled behavior

**Prepare and application:** inside the same already acquired `BEGIN IMMEDIATE`, first decode fixture state and call B's `prepare_on_connection(conn,t)`. Never accept an externally prepared plan. A validates current authority, old estimate versions, source/contribution attribution, immutable snapshots, compact envelopes and tombstones; B derives checked sums from latest quotes and original/null/absent bindings. No fresh catalog or `persist_current` during preparation/application. Keep those semantics intact.

Consume the plan on that same connection, with all fallible work in the outer transaction:

1. Upsert each surviving compact payload with `CompactValues::encode`; insert missing snapshot references using the exact thread/day/snapshot key. Existing references are unions, not a replacement that loses another retained price version.
2. For every raw removal, insert only the anonymous UUID/expiry tombstone when `expiry > t`. A already rejects raw/tombstone collisions; do not mask them with an expiry-extending upsert. Delete contribution, all estimates, binding, observations and attempt in that FK-safe order.
3. Delete expired compact references before expired compact days. GC snapshots with **both** `NOT EXISTS(raw bindings)` and `NOT EXISTS(compact references)`. An unused alternative catalog snapshot may also be GC'd; retain every referenced snapshot payload exactly.
4. Delete tombstones with `expires_at_ms <= t`; update the sole checkpoint and activation bit together. The replay floor derived from this time advances in the same transaction as pruning. Verify exactly one checkpoint was updated.
5. Commit once, or return an error and complete rollback. A failed commit is never success; allow SQLx's transaction cleanup to complete before subsequent reads. Repeat after an uncertain outcome by reopen-and-maintain, not by applying a remembered plan. Successful repeats promise identical logical accounting rows, not zero SQLite physical writes.

`delete_on_connection` first runs maintenance at the requested time, then removes the target owner's remaining raw attempts and compact refs/days even if raw ownership is empty. It reuses private raw-removal/GC helpers within the atomic module; no externally callable partial transfer helper. Run GC again after removing the target. Retain only unexpired anonymous tombstones. Failure in target deletion rolls back the maintenance, checkpoint/floor, activation and every representation too. No independent inner commit or nested transaction-owning lifecycle/estimate call.

**Admission after activation:** decode the durable state in Journal's existing write transaction before inserts; retain its tombstone guard and identity/retry/revision checks. At checkpoint c, reject future dispatch `d > c`; compare checked `d+365d` first and reject equality/older even when its UUID tombstone is gone. For remaining `d+90d <= c`, return explicit **unsupported compact-only late import in this fixture**, without writes. This is unqualified 90..365-day import coverage pending later S02 work, not a blanket product rejection or shortened replay policy. For `d+90d > c`, preserve existing validation/admission. A tombstoned UUID cannot evade suppression by claiming a different dispatch while its replay record exists. A retry whose predecessor was erased remains explicitly unsupported by the existing ancestry check; no hidden identifying ledger.

The fixture's admission clock is the last completed explicit as-of. Future dispatch requires maintenance to advance it first. No wall-clock/current-time guarantee is inferred from Journal's clockless API. Recent new UUIDs for a deleted native thread remain outside fixture ownership qualification. Identity protection after the approved replay horizon is not permanent UUID memory.

**Reads:** absent schema is not a retained fixture; staging returns NeedsActivation. Malformed/active-NULL state errors. Reject negative requested time/day, backward requests, future day, and checked time arithmetic overflow. For requested t greater than c, return NeedsMaintenance without advancing c. Pending cleanup cannot be Ready; return NeedsMaintenance. Source/envelope/overflow corruption errors, not unknown totals.
