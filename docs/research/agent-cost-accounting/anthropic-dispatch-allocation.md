## Concrete runtime contract

### Activation, native ownership and failures

Add an in-memory Core `Config` mode, Disabled by default. The enabled variant binds an opaque local endpoint/account scope UUID and an explicitly approved direct Anthropic endpoint. It carries no key, credential fingerprint or arbitrary supplied rate. The ordinary config loader always initializes Disabled: no TOML/CLI/env/Feature entry, config schema, TUI control or default installation in this unit. A native embedding can explicitly set this normal-library configuration and execute the existing native user-turn path; this is not a cfg(test)-only collector.

The production binding uses the built-in direct endpoint `https://api.anthropic.com/v1`. A test embedding may explicitly bind its isolated loopback endpoint and synthetic auth in the same typed in-memory configuration. Do not infer that trust from a user-edited provider base URL. This explicit endpoint binding is application trust configuration, not a new auth principal or permission to dispatch. Changing the provider route must fail the binding check before collection, not silently apply direct prices to a gateway. Do not persist endpoint URLs or credentials: attempts use the opaque bound scope and bounded provider ID.

The scope UUID identifies the application's selected local account/endpoint context, is reused across retries and config-inherited children, and is supplied again by the embedding on resume. It is not an invoice account identifier, security capability, credential-derived ID or newly registered identity. Authentication and provider authorization remain exclusively in the existing machinery. Public-list estimates do not claim negotiated/account-specific invoicing rates.

OFF must bypass accounting setup entirely, including when `StateDbHandle` is None. An already installed store must still receive the existing atomic native deletion cleanup while OFF. When ON, materialize the native owner using the existing strict path, obtain the optional state handle as a required dependency, and explicitly open/activate the accepted store before the supported sampling dispatch. Missing/failed database or owner, unsupported schema, failed activation and failed admission produce a bounded non-retryable accounting failure and zero provider sends; never degrade to unrecorded ON collection. Existing ordinary startup remains optional and unchanged for OFF/unsupported routes.

Use the existing `CodexErr::Fatal` classification (`protocol/src/error.rs::is_retryable` returns false), not a new protocol error variant. At the HTTP boundary admission failure maps to non-retryable `TransportError::Build`; retain an accounting-failure latch in the logical request context so API error mapping and Core stream retries cannot accidentally turn persistence errors into another send. Check the latch before Core retry decisions and before a successful sampling result. Error text must not expose SQL, home paths, credentials or response bodies.

After a send, an observation failure terminates this sampling request without a repair send, keeps already committed intent/evidence and leaves unobserved usage unknown. Cancellation retains committed evidence. Use awaited observation writes, not a detached persistence queue; cancellation may leave either the complete committed observation or the previous complete state, never a synthetic completion. Reopen reads the accepted store and resumes normal native history; it does not infer missing usage from cumulative rollout `TokenCount` or automatically replay a previous network send.

Store timestamps remain explicit and exact. Sample fresh wall time immediately before each facade operation after caller-side waits; handle a rejected stale/backward time as a visible accounting failure. Do not clamp with a checkpoint, silently coerce explicit time, reset activation, or assume that a timestamp sampled before an awaited writer is ordered. This collector does not change the store's explicit-time API or claim to repair cross-process clock skew. Native deletion's reviewed writer-owned production clock remains untouched.

### Physical attempts and original identities

The logical context is owned by one native `ThreadId`, native turn ID and one `run_sampling_request` invocation. Create its random request UUID once; each invocation of the accounting transport's `stream` allocates a fresh attempt UUID, links `retry_of` to the previous attempt in this logical request, and durably admits that exact identity before delegating to Reqwest. Capture the exact encoded request model and resolved supported route for the attempt, not a fuzzy catalog alias or stale display model.

HTTP429/5xx/transport retries, signed-history/413 rebuild retries and Core consumed-stream retries must all preserve logical identity but acquire a distinct attempt identity on each actual send. A reconnect notice is not a send. Auth, encoding or stage-one preflight failure before this boundary creates no dispatch attempt. Admission is durable intent, not proof that bytes reached the provider: a crash immediately after admission remains an unknown attempt. Retries can each consume tokens, even without provider request IDs.

Do not change Corbanu gateway request-ID rotation, reservation release handling, auth recovery, native inference trace IDs or provider headers. Missing/reused provider IDs cannot merge accounting attempts. Direct API-key auth normally has no refresh recovery (`unauthorized_recovery` returns None when the provider has an env key); test its actual401 terminal behavior rather than inventing a direct-provider auth retry.

Bind the usage observer to the correct physical successful response: each endpoint-client invocation gets its own shared success slot, populated once by its transport adapter only when the successful `StreamResponse` is returned. Failed HTTP attempts remain admitted but do not fill the slot. The SSE observer captures that immutable successful-attempt handle. A later endpoint/outer retry gets another slot; never attach old-stream usage through a mutable logical-request-wide “current attempt”. This avoids modifying the generic HTTP response type or every provider API.

### Actual SSE token presence and durable source positions

Add an optional, awaited typed observer on `AnthropicMessagesClient`; default None avoids new accounting parsing on all existing callers. Put the small wire DTO/observer trait in a dedicated API module, re-exported from the existing API lib. API has no dependency on Core or state. Nest the module using an explicit path declaration from `anthropic_messages.rs`, avoiding an otherwise unnecessary endpoint module-list edit.

Before the existing lossy deserialization, extract only `message_start.message.usage` and `message_delta.usage`: `input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `output_tokens`. Preserve each as Missing, explicit Null or exact nonnegative integer, including explicit zero. Reject negative, fractional, string, boolean and out-of-i64 numeric forms for enabled accounting. Absent/null usage containers provide no invented numeric fields. Ignore non-usage content and unrecognized provider metadata; never pass whole messages, bodies, text, reasoning, headers or auth to the store.

Map to the existing `Dialect::NativeAnthropic` and `Patch`; do not subtract caches from Anthropic noncached input. Do not invent reasoning or total fields; use accepted state derivation only when its required components are known. A null patch does not erase a previous known count, omitted fields do not become zero, and cumulative revisions replace rather than add. Preserve the old `TokenUsage` and ResponseEvent surfaces and their existing tests.

The physical stream has an immutable source UUID and a strictly increasing wire source position assigned by the sequential SSE parser, starting at one. Persist that original position as revision/sequence on the attempt; do not derive ordering from wall clock or callback completion order. An identical local persistence retry reuses the original tuple, not a new revision. A new physical stream is a new attempt/source. There is no historical source reordering or provider-reconciliation importer in this unit.

Await durable storage of each recognized usage event before exposing its derived response events/completion downstream. Stop on persistence/validation failure. Ensure the observer also sees start-only usage when the provider subsequently errors, disconnects or the caller cancels. The completion callback alone cannot recover missing start-cache fields.

### Trusted original prices, not arbitrary caller snapshots

The production adapter constructs snapshots itself from `codex_models_manager::bundled_models_response()`. Select exactly one exact model slug with `ModelOrchestrationMetadata::Eligible`, provider ID anthropic and `ModelBilling::Metered`. No fuzzy prefix lookup, remote-only row, model display text, subscription pricing, wallet balance, Corbanu price response or request-supplied price can authorize this snapshot.

Concrete existing evidence: bundled `claude-opus-5` carries input5000/output25000/cached-input500 milli-USD per million; `claude-fable-5-1` carries10000/50000/1000. These are repository catalog facts, not live market-price verification. Convert integer milli-USD to exact USD decimal strings by integer quotient/remainder, never floats or early rounding. Bind noncached input/output and optional cache-read only. The bundle has no cache-write rate: retain NULL rather than infer a multiplier, TTL or tier. Nonzero cache-write usage therefore leaves that price component unknown; explicit zero needs no rate under the existing engine.

Use `SourceKind::NativeCatalog`. Derive `source_reference` with the existing UUIDv5 capability over a documented canonical tuple of projection-version, exact provider/model, units and the selected raw billing fields. This is a reproducible content identity, not a claimed cryptographic authenticity proof. Persist all selected exact rates and scope through `AccountingStore::admit`; missing/unsupported/ambiguous catalog matches bind no price and remain unknown. Do not block measured token collection just because a trusted price is unavailable.

Catalog rows have no upstream effective date. The collector's explicit native opt-in approves that bundled projection prospectively for estimates: observed/approved/effective-from share the local acceptance timestamp, no earlier than capture and no later than that attempt's dispatch. Never claim that it is the provider's historical price start. Freeze the binding before admission and use it for every observation of that attempt; a later catalog/route/config change cannot reprice it. New attempts can bind their own prospective snapshot. No retrospective re-estimation or billing reconciliation is added.
