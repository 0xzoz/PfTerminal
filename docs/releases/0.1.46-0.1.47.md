six-model benchmark of 0.1.47 against Hermes, and the fixes found since that are

### 0.1.46: provider and agent-loop fixes

| Problem | Effect before the fix | Fix |
| --- | --- | --- |
| Vercel rejected every server-side continuation (`previous_response_id`) for some models, and Corbanu retried it every turn | 44 of 98 requests in a Kimi K3 run were failed round trips | After the first rejection the session sends full context |
| A synthetic `Continue.` user turn was added whenever history ended in model output | The model read it as the user and re-checked finished work | Added only for a real assistant prefill |
| GPT-6 Sol calls the code-mode `exec` tool as a function over Chat Completions; the handler accepted only freeform calls | Every call aborted: Queryforge 1/12, one run looped for 235 requests | Both call shapes accepted; 38/38 hidden tests afterwards |
| Freeform tools were wrapped with `strict: true` | One unescaped quote let the model emit 65,536 tokens of whitespace ($0.66, about 11 minutes), in 2 of 3 runs | Wrapper no longer strict; malformed calls stay visible to the model |
| GLM on Vercel was pinned to Z.AI, which zero-data-retention accounts may not use | Every GLM 5.3 and GLM 5.3 Flash request failed | Falls back to gateway routing when the gateway skips every provider |
| The identical-call guard counted per model request, not per turn | GLM 5.3 Flash repeated one command 156 to 250 times (up to $1.35 per run) | Turn-level guard: refuse after three identical calls in a row, stop the turn at the eighth |

## First benchmark: Corbanu 0.1.47 against Hermes, six models

### Method

- **Harness:** repository harness `benchmarks/coding` (branch
  `bench/leakproof-openrouter`). Each run gets its own container with only the
  task workspace and an empty home. All traffic goes through a relay that holds
  the key, pins the model and host, and records every request, response and
  charge. Contestants cannot see hidden tests or verifiers.
- **Contestants:** the released Corbanu 0.1.47 Linux package, and Hermes
  v2026.9.24 (Hermes Agent 0.21.5, released that day). MiMo V2.6 Pro is not in
  0.1.47's model list, so its Corbanu lane used a local build of 0.1.47 plus the
  MiMo catalog entry.
- **Settings:** OpenRouter for every model, with the same host pinned for both
  tools. Both tools used reasoning level `high`, checked in the recorded
  requests.
- **Tasks:** the ten core coding tasks (the full catalog minus the website task).
  One run per task per tool, with a 20-minute limit and 4 CPUs and 8 GB per run.
- **Scoring:** hidden tests passed. A task counts as fully passed only when
  every hidden test and the visible tests pass and the run ended within the time
  limit.

Reading the results:

- **Strong models:** on Opus, Kimi and DeepSeek, Corbanu matched or beat Hermes on
  correctness and was cheaper and faster (Kimi: 43% cheaper, 44% faster).
- **GLM:** Corbanu trailed on both GLM models. It made about 1.7 times as many
  requests as Hermes and fully passed fewer tasks. See the GLM 5.3 Flash
  follow-up below.
- **MiMo V2.6 Pro:** served at about 37 tokens a second, so both tools often hit
  the 20-minute limit (Corbanu 4 times, Hermes 5). Hermes scored nothing on two
  tasks and 1/12 on a third after stalled requests, which explains most of its
  lower score. Treat this row as indicative.
- **Sample size:** these are single runs, so small per-task differences are noise.
  In repeated rounds of GLM 5.3 Flash (below), Corbanu fully passed 3, 5 and 3
  of 10 tasks.

### Test grading corrections

During these benchmarks, several hidden tests turned out to check things the task
instructions never asked for. Every model and both tools failed them. They were
corrected without revealing hidden tests to contestants, and every run above was
re-graded:

- **chronoledger, logtriage and rategate** required exact error or diagnostic code
  names the prompts never gave, such as `imbalanced_transaction` and
  `invalid_timestamp`. They now require a stable, non-empty code; codes the
  prompts do name are still checked.
- **queryforge** required the words "unexpected" or "syntax" in an error message
  the prompt only calls "useful". It now requires a non-empty message.
- **Test integrity** rejected runs that added test files, although prompts only
  forbid removing tests. Added files are now recorded but allowed.
- **Build-from-spec prompts** named a test command that could not import the
  package from `src/`, while the grader required it to stay there. The prompts
  now give the grader's command.

**textwright is unchanged:** its prompt describes one of the five bugs its hidden
probes check. Only Opus found most of them (4/5), and every other model scored 1/5.

## Found since 0.1.47 (not yet released)

These are committed on `fix/responses-synthetic-continue-only-on-prefill`.

| Change | Evidence |
| --- | --- |
| **Retry transient shared-pool rate limits.** OpenRouter marks brief upstream saturation with `error.metadata.limit_source = "upstream_provider_shared_pool"`. Corbanu now retries these four times (2, 4, 8, 16 s, honoring `Retry-After`); every other 429 keeps the no-retry behavior | In the first DeepSeek V4.1 Flash run, 9 of 10 tasks ended within one second on such a 429, while Hermes waited it out. That run was discarded and repeated on another host |
| **Add OpenRouter MiMo V2.6 Pro** to the model list | 1,048,576-token context, 131,072 max output, low/high reasoning |
| **GLM 5.3 Flash work pattern.** A short block after the standard base's opening paragraph: batch independent calls, write complete implementations, check every requirement by execution, finish only when verified. Applies to the Z.AI, OpenRouter and Vercel GLM 5.3 Flash routes | See the follow-up below |

### GLM 5.3 Flash follow-up

Setup: ten tasks, the same Z.AI host, reasoning `high`, and two or three rounds
per setup.

| Setup | Tasks fully passed | Hidden tests passed | Requests per task | Reasoning tokens per request |
| --- | --- | --- | --- | --- |
| Corbanu 0.1.47 as shipped | 11/30 (37%) | 86% | 23 | 251 |
| Corbanu, reasoning replay off | 6/20 | 75% | 44 | 41 |
| Corbanu, "think first" wording (run stopped early) | 5/16 | 85% | 21 | 335 |
| **Corbanu with the work pattern** | **13/20 (65%)** | **91%** | 27 | 224 |
| Hermes v2026.9.24 | 19/30 (63%) | 91% | 15 | 503 |

What the transcripts show:

- **How the model worked:** under Corbanu, GLM 5.3 Flash reasoned about half as
  much per step and built modules through long chains of small edits. On
  eventforge, Hermes's GLM reasoned for about 15,000 tokens and then wrote the
  whole module at once. Corbanu's reasoned for about 6,000, wrote part of it, and
  patched it 25 or more times.
- **Batching:** Hermes's GLM batched several tool calls in one response in about
  30% of turns, against about 2% under Corbanu. Hermes's system prompt (about
  14,000 characters) spells out rules for batching, finishing the job and
  verifying with real tool output. Corbanu's standard base for open models is
  about 1,300 characters and asks for speed and concision.
- **Ruled out:** request parameters and reasoning replay. Swapping parameters did
  not change how deeply the model reasoned, and turning replay off made results
  worse.
- **Only on GLM 5.3 Flash:** the other open models keep the unchanged standard
  base, because Corbanu already leads on them.

## Open items

- **GLM 5.3 (non-Flash)** has no OpenRouter catalog entry in 0.1.47 and runs on
  fallback defaults. It also trailed Hermes. Next step: add an entry with
  reasoning replay and the work pattern, then re-benchmark.
- **Repeated runs:** single-run results are noisy. The six-model benchmark should
  be repeated before any public comparison.
- **Release cadence:** the three-release benchmark cycle in
  [`benchmarks/README.md`](../../benchmarks/README.md) remains incomplete. These
  runs are diagnostics, not a qualifying cycle.
