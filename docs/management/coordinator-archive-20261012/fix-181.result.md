I've merged the fix for #181 as **PR #189** (merge commit `6d65f78ebe`), and #181 closed automatically. The Baseten and OpenRouter Anthropic routes now have an output limit for every model they can reach, so turns no longer fail with "has no catalogued maximum output token limit".

**How I picked the numbers:** this route asks for the full limit on every request and never lowers it as the conversation grows. OpenRouter rejects a request when the input plus that limit is bigger than the model's context window. So I used each model maker's documented limit or default rather than OpenRouter's larger listed maximums, and checked each one against OpenRouter's per-provider listings (fetched 2026-10-06 06:56 UTC).

| Model | Limit | Source |
|---|---:|---|
| `zai-org/GLM-5.2` (Baseten) | 128000 | Z.AI documents a 128K max output; Baseten's own OpenRouter listings allow 262144 |
| `z-ai/glm-5.2` (OpenRouter default) | 128000 | Z.AI 128K; every OpenRouter provider for it allows at least 128000 |
| `moonshotai/kimi-k3` | 128000 | Moonshot's default is 131072; I used 128000 to match the Vercel Kimi row, because the Vercel route also uses this row |
| `minimax/minimax-m3` | 131072 | MiniMax's recommended value (hard max 524288). MiniMax's own 512000 would leave only about 12K tokens for input |
| `google/gemini-3.5-flash` | 65536 | Every OpenRouter provider |
| `deepseek/deepseek-v4-pro` | 384000 | Same as the direct DeepSeek and Vercel rows |
| `deepseek/deepseek-v4-flash-0731` | 384000 | Same as the direct DeepSeek flash rows |
| `x-ai/grok-4.5`, `x-ai/grok-4.6` | 128000 | **Conservative default:** xAI documents no separate output limit, and OpenRouter's 450000 would break any conversation past about 50K tokens |
| `tencent/hy3:free` | 128000 | **Conservative default:** the free version has no live providers; Tencent's own listing for `tencent/hy3` is 128000 |
| `openrouter/owl-alpha` | 262144 | **Couldn't verify live:** the model is retired; this is its last published OpenRouter listing (it's a hidden model) |

I also lowered `x-ai/grok-4.7`, which was already on main, from 450000 to 128000 for the same reason; the reviewer flagged it.
