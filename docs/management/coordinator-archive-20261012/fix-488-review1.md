Problem (#488, macOS Seatbelt): when the workspace is reached through a nested link (`.../link -> .../real`), a denied path such as `.../real/.env` was not excluded from the readable root `.../link`, because exclusions were attached by literal `starts_with` before canonicalization, while Seatbelt enforces canonical paths. Agent commands could read the denied file while the Aggressive launch check reported it as protected. Owner decision: protected reads are never grantable under Aggressive and a denial must hold.

The change:
1. sandboxing/src/seatbelt.rs: each denied path is attached to every readable root that reaches it (literal match OR canonical spellings of both sides), and each exclusion is emitted in the spellings Seatbelt matches (canonical, plus nearest-existing-ancestor resolved for paths not created yet). The same canonical attachment is applied to writable roots (denied paths only), and exclusion spellings are deduped. Read clauses are built once (`seatbelt_read_access`) and shared by `create_seatbelt_command_args` and the new pub `seatbelt_allows_file_read`.
