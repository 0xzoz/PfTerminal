Fixes #467. Bounded fix. Product spec: "P0 `/security` levels › Product surface": "Aggressive is an explicit lockdown posture, not a marketing label." This restores a correct launch report and doesn't change any sandbox rule.

**Cause.**
- Launch denies credential paths computed from `current_dir()`, which is resolved (`/private/tmp/…/workspace/.env`).
- The launch re-audit spells the same file from the config cwd (`/tmp/…/workspace/.env`).
- `verify_isolation` compared the two spellings literally, so it reported `.env` as readable.
- Seatbelt and bubblewrap enforce on resolved paths: the denial was in force, and only the report was wrong.

**Fix** (after review round 1).
- New `FileSystemSandboxPolicy::can_read_effective_path_with_cwd`. It normalizes the policy's paths and the path the way the sandbox normalizes its roots (`normalize_effective_absolute_path`): top-level aliases such as `/tmp` → `/private/tmp` resolve, and nested links stay as written.
- Seatbelt attaches a denial to a readable root only when those normalized spellings match. A rule reached only through a nested link is therefore still reported, never claimed.
- The first version resolved every link. The reviewer showed that this could claim a denial Seatbelt doesn't enforce, so it was replaced.
- `verify_isolation` uses the new check. A path no rule denies is still reported (tested).
- The `/security` current-values rows now also recognise the current folder by its normalized spelling. That mismatch is what made `security::current`/`security::aggressive` tests fail with `TMPDIR=/tmp`. They now pass with both `TMPDIR=/tmp` and the default.

**Tests.**
- `security::aggressive::tests::isolation_is_verified_through_tmp_on_macos`:
  - It covers a workspace under `/tmp` denied by its `/private/tmp` path, and the reverse, checked through both spellings.
  - An undenied file is still reported.
  - It fails on main (verified by reverting the one-line switch).
- `security::aggressive::tests::isolation_through_a_nested_link_is_still_reported`.
- protocol `permissions::tests::can_read_effective_path_matches_through_top_level_aliases` (macOS; also covers a file not created yet, a relative path, and the literal check that #467 reported) and `can_read_effective_path_keeps_nested_links_apart`.
- `cargo test -p codex-tui --lib -- security::`: 88 passed with `TMPDIR=/tmp` (4 failed on main) and with the default TMPDIR. Protocol `permissions` tests: 46 passed.
- Clippy `-D warnings` is clean on macOS and on Linux (glitch, plain and developer-accounting).
