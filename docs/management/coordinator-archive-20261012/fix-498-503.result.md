# #498 and #503 (Linux sandbox): result

Both fixes are merged with every check green and none pending. #498 and #503 are closed with evidence comments, and #498 records Travis's decision.

## What shipped
- **#508 → #498, merged `49c6eb66dc`.** The no-denial full-write bwrap path (full disk write with a managed proxy) now mounts a fresh `/dev` after `--bind / /`, so `/dev/null` works. On this path, Permissive sandboxes now see the minimal `/dev` (14 entries instead of the host's 229), and `/dev/shm` and `/dev/pts` are private.
- **#511 → #503, merged `dbf278f833`.** Writable roots are ordered and compared by their real (canonical) path, so a writable symlink to `/` is treated like `/`.
  - Review found that this ordering alone could drop protections in some cases: two roots binding the same folder, or a link target nested inside another root. Each pass now re-applies the read-only paths and denials that earlier passes set below its folder. For a link, that includes the folder itself.
  - Stricter, never weaker: a writable link can no longer reopen a path another root made read-only. Example: a link to a workspace's `.git`. macOS Seatbelt still allows that, judging from the code (not tested). This is disclosed in the PR.
