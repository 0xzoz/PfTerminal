**Decision for Travis (#245, Moderate).** Both changes are limited to protected credential and vault paths, so I merged rather than marking it for sign-off:
1. A person approving an additional-permission read of a protected path under Moderate is now refused before the prompt. The docs don't describe that approval as a way to grant access, and #245 lists Moderate as affected, so I treated it as the gap. I recommend keeping it; the alternative is to let a person's fresh approval lift it, like #239.
2. Additional write permissions at or under a protected folder (for example `~/.ssh/authorized_keys`) are also refused. A write permission also lets the command read the path, so this is the only way to keep the read protection.
