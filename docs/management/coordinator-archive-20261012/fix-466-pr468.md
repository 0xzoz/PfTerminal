Fixes #468. Bounded fix. Product spec: "Shipping MVP — LIVE", Agent orchestration row: "Sauron → Nazgul → Troll → Orc orchestration, model-aware delegation". /spawn already starts an agent with the chosen model and effort; this restores that for Max/Ultra and adds no new behaviour.

**Cause.** The "More reasoning…" item sent `OpenAdvancedReasoningPopup { model }` without the popup's purpose, and the Max/Ultra popup always built the `/model` session actions (`UpdateModelSelection`, `UpdateReasoningEffort`, `PersistModelSelection`, or `ApplyAdvancedReasoning` for Ultra). From /spawn → Troll → GLM 5.3 Flash → More reasoning… → Max, that tried to save the main model. The save was refused ("Cannot save `glm-5.3-flash` because provider `zai` is inactive or unavailable") and no pane opened.

**Fix.**
- `OpenAdvancedReasoningPopup` now carries `purpose`.
- For a spawned agent or a new Corbanu Terminal pane, the Max/Ultra item sends `CreateSpawnAgent` / `OpenCodexPaneNamePrompt`. This goes through the same helper as the standard efforts, so the session model is neither changed nor saved.
- For `/model` (the Session purpose), behaviour is unchanged.
- In the spawn case the advanced popup no longer marks the session's current effort as "current".
- Ultra for a new pane or spawned agent shows the same multi-agent concurrency warning as the session path (review round 1).

**Tests.**
- `chatwidget::tests::popups_and_settings::spawn_advanced_reasoning_spawns_instead_of_saving_session_model`, for Max and Ultra:
  - The More reasoning… event keeps the spawn purpose.
  - Enter emits `CreateSpawnAgent { role: Troll, parent, model, effort }`.
  - It emits none of `PersistModelSelection` / `UpdateModelSelection` / `UpdateReasoningEffort` / `ApplyAdvancedReasoning`.
  - The same holds for a new Corbanu Terminal pane (`OpenCodexPaneNamePrompt` with the effort).
  - The Ultra warning appears for Ultra only.
- The existing `/model` advanced-reasoning tests still pass: 184 tests in popups_and_settings, plan_mode and model_popups.
- macOS clippy `-D warnings` (codex-tui, all targets) is clean. Linux clippy and the tmux run are in the comments below.
