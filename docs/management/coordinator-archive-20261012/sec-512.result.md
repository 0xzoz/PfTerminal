I merged PR #517 (merge commit e6ea94d990) and #512 is closed with an evidence comment. The test was right and the product was wrong, so I left the test unchanged and fixed the product.

## What was wrong
- **The bug:** before an Apps file upload, the check `readable_under` (in `read_denials.rs`) resolves the file's links to its real path. It then compares that real path with the denied paths, but those were written the way the Corbanu home was configured. When the home is reached through a link, the real path never matches any denial.
  - Common cases are macOS `/tmp`, the macOS default `/var/folders/…`, or a home folder that is itself a link on any OS.
  - In those cases a link to a denied file (e.g. one pointing at `auth.json`), or the denied file under its real name, passed the check.
- **Why it matters:** for profiles with full write access the upload read runs outside the sandbox, so this check was the only protection there.
- **Linux is affected too** when the home is reached through a link. A new test fails on unfixed main on glitch.

## The three questions
1. **Since when:** since PF-23-S01 (commit a58a5e18e6, merged in #233 on 2026-10-06). The code has had this flaw since then, so I didn't need to bisect. On macOS the test fails whenever TMPDIR sits under a link, which includes the default.
2. **CI coverage:**
   - **Before:** no job ran codex-core tests on macOS, and no PR job ran them at all. Only postmerge ran this test, on Linux, where `/tmp` is not a link, so it passed.
   - **Now:** a new reusable workflow, `rust-ci-core-security.yml`, runs core `security::` tests twice: once with the runner's TMPDIR and once with `TMPDIR=/tmp`. It runs:
     - on PRs, on Linux and macOS, as part of the required CI gate;
     - after merge, on macOS.
   - **Workflow push:** GitHub accepted the push without needing an approval.
3. **Product or test:** the product. The fix adds a stricter check that resolves links in the denied paths too. It can only block more, never allow more. Permissive is unaffected because the upload check doesn't apply there.
