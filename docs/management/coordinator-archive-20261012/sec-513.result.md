**#514 and #523 (key presses answering prompts)**
- **Link and tool-suggestion view (#514):** a number key now only highlights; Enter confirms. Typed text, Tab, pastes and held keys never answer. "Enable app" lasts beyond the request, so only the arrows choose it. A double Enter can't confirm "I already installed it". Views you open yourself through `/apps` are unchanged.
- **Main approval prompt (#523):** when it opens over another view or reappears after the view above closes, Enter alone does nothing; you must pick with the arrows first. An open "Grant once" review goes back to the approval, so a double Enter can't grant.
- **Any prompt shown within 1 second of another closing:** needs a choice before Enter.
- **MCP forms that open while you're typing or over another view:** take no text, pastes, edit keys or shortcuts until you use the arrows.
- **Paste or timer closing a view:** only that view closes; an approval waiting underneath stays.

**Decision for you (#513, Moderate):** under Moderate, an approved extra write permission can still open shell and git startup files, git hooks and config, and the project's `.codex` and `.agents`. I left this unchanged, and a test case pins it.
- **Recommendation:** refuse these too, as for the runtime files. These files run code later, outside the sandbox. A person can still approve running the command outside the sandbox, which is the existing documented route with its warning, so nothing becomes impossible.
- **Trade-off:** someone (or Guardian, or a hook) approving "write `.git/hooks`" as an extra permission gets a refusal instead.
- **Alternative:** keep it, since a person approved it.
