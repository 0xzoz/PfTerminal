## Finding
- **Product bug, not an outdated test.** The test is unchanged and still strict.
  - **What was wrong:** the Apps upload check `readable_under` resolved links in the file's path but compared the result with denials written through the configured home.
  - **Effect:** when the Corbanu or user home was reached through a link (`/tmp` or `/var` on macOS, or a linked home on any OS), a link to a denied file, or the denied file under its real name, passed the check.
  - **Why it matters:** for full-write profiles the upload read is unsandboxed, so this check was the only protection.
- **Since when:** PF-23-S01, merged in #233 on 2026-10-06 (a58a5e18e6). The code was always like this, so no bisect was needed. On macOS the test fails whenever TMPDIR is under a link, which includes the macOS default `/var/folders`. It passes only with a TMPDIR that has no link in its path.
- **Linux:** affected too with a linked home. The new test fails on unfixed main on glitch.
- **CI:**
  - **Before:** no job ran codex-core tests on macOS, and no PR job ran them at all. Postmerge Linux nextest ran this test, but on Linux `/tmp` is not a link, so it passed.
  - **Now:** the new `rust-ci-core-security.yml` runs core `security::` with the runner's TMPDIR and with `TMPDIR=/tmp`. It runs on PRs on Linux and macOS as part of the required gate, and postmerge on macOS.
  - **Workflow push:** accepted; no approval was needed.
