I opened **PR #499** for #488. It is not merged and stops for your security sign-off. All 27 PR checks pass (9 skipped), it merges cleanly with main, and it says "Refs #488". Linux was affected too, contrary to what the issue says, so the PR also fixes the Linux sandbox (bubblewrap).

## What becomes denied that was not before
Only paths the policy already denies, through spellings the sandbox used to miss:
- **macOS, workspace opened through a link** (`…/link -> …/real`): agent commands could read and write `real/.env` even though it was denied. They no longer can, through any spelling. The same now holds when the rule says `link/.env` and the workspace is opened as `real`.
- **macOS, denied files that don't exist yet:** a denied path under a linked folder (e.g. `link/later.key`) could be created and then read. It can't be created any more.
- **Linux, same nested-link case:** a denial spelled with the workspace's real path was never applied, so a sandboxed `cat` printed the file. It is blocked now.
- **One side effect the reviewer asked me to state:** if the policy denies a link that points at a folder agent commands can read or write, that whole folder is now denied too. This only happens when the policy denies a spelling of that folder.
- **Nothing the policy allows becomes denied.** Tests check every added exclusion in the generated sandbox rules. A more specific allow inside a denied folder still works, also across links.

## What changed
- **macOS sandbox (`seatbelt.rs`):** each denial is now applied to every folder that reaches it, comparing both sides with links resolved. Exclusions are written the way the macOS sandbox matches paths, including denied paths that don't exist yet.
- **Launch check (`verify_isolation`):** on macOS it now builds the same rules the sandbox uses, through one shared function, so it can no longer report a path as protected when it isn't. Other platforms are unchanged.
- **Linux (`bwrap.rs`):** denials under a workspace reached through a link are now applied after the workspace is mounted.
