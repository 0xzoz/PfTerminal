01 · Engineering decision

Build a small experiment service around LangGraph for coordination, a transactional evidence ledger inspired by Danus, and a dedicated GPU execution harness. The reusable product is a system for conducting and remembering defensible experiments. GPU kernel optimization is its first domain adapter.

Status: proposed engineering design, 2 October 2026. This document authorizes no implementation sprint, GPU reservation, paid experiment, production deployment, or automatic kernel merge. The current work is a Routine internal research artifact. Implementing the service is a separate Product initiative requiring the repository’s product-scope decision, active plan, and ready sprint records.

The existing systems cover useful pieces, but the research did not establish a single drop-in system that combines durable agent workflows, revocable evidence dependencies, trustworthy kernel checking, exclusive GPU measurement, recovery, and campaign accounting. Integrate established orchestration; build the domain’s acceptance and execution boundaries. Do not make a conversation transcript or a checkpoint the authority for whether a kernel is correct or faster.

02 · Research and build-versus-adopt

Cogentic combines parallel exploration, adversarial draft and cross-draft review, retained failed attempts, separately rechecked intermediate results and process adaptation. Its evidence concerns natural-language mathematical research; it does not establish GPU measurement correctness or the causal benefit of every component. We adopt its experiment structure as a hypothesis to test, not a performance guarantee. [R1]

Danus separates scratch work, shared awareness and accepted facts, uses content-derived fact identifiers, gates fact submission through a verifier, and supports dependent-fact revocation. Its verifier is an LLM, not a formal proof checker. The inspected implementation uses files and role-gated tools; its runtime/security assumptions are unsuitable as the GPU execution boundary. Our design retains the memory separation and dependency semantics but replaces admission, storage and execution. [R2]

04 · Architecture and trust boundaries

One authority for each responsibility

LangGraph stores resumable workflow state: campaign ID, policy digest, candidate IDs, pending job IDs, evidence references, iteration number and remaining request budget. It does not store raw tensors or authoritative job completion. Use explicit reducers for parallel proposal results, deduplicate by candidate ID, bound fan-out, and keep reducers free of side effects. Checkpointers persist per-thread execution; shared knowledge belongs in the domain ledger. [R3][R4]

The control service owns campaign authorization, validation, budget reservations, artifact registration, claim admission and revocation. Its PostgreSQL schema is separate from LangGraph checkpoints. Use a transactional outbox for dispatch and an idempotent inbox for runner receipts. Keep this in one deployable service initially; module boundaries do not require microservices.

The runner owns physical execution, isolation, durable start/finish journaling and measurement. It authenticates to the service outside the candidate environment. Source and logs are untrusted data: they cannot issue tool calls, change policy, or add claims. The candidate receives only its declared ABI, inputs and output buffers; no model credentials, database connection, expected-output files, host sockets or network access.

The operator owns host enrollment, device maintenance, policy approval and uncertain recovery. Model-generated explanations are recommendations. Operational approval records bind actor, action, manifest digest, timestamp and expiration; a changed manifest invalidates the approval.

04a · Worker contribution protocol

Separate how contributors receive work and return artifacts from how the service schedules execution and accepts evidence. Corbanu agents, other coding agents and human contributors should use the same versioned contract. LangGraph remains the internal workflow engine; it is not a mandatory runtime for a contributor. This protocol is an application-owned design inspired by Choir, not a claim of wire compatibility with Choir.

Choir coordinates independent contributors through repository tasks and submissions. Its useful architectural lesson is to let attempted work refine the plan while the project retains acceptance authority. We adopt those ideas without making a GitHub issue, a worker narrative or a green status badge an authoritative experiment record. [R23][R24]

Decomposition is progress, not proof of the parent

Maintain task states separately from claim validity: proposed → published → assigned → submitted, with reviewed submissions resulting in rejected, decomposed/open or qualified/closed. Task closure requires its completion predicate, not a merged source patch. Each transition is an append-only domain event; external issue labels are projections.

An accepted split creates approved child tasks and leaves the parent open. Completed children can enable the parent's integration experiment. They cannot establish its performance by adding or multiplying their speedups: fusion, layouts and scheduling can interact through occupancy, register pressure and memory traffic. Require the original end-to-end numerical and performance qualification on the assembled candidate. Reject tautological splits that merely restate the parent, cycles, unauthorized contract changes and proposals that spend beyond the campaign ceiling.

def accept_decomposition(proposal, authorized_reviewer):
    with transaction():
        lock_project(proposal.project_id)
        parent = load_current_contract(proposal.parent_task_contract_hash)
        require_open_parent_and_reviewer_capability(parent, authorized_reviewer)
        validate_child_contracts_and_nontrivial_split(proposal)
        require_acyclic_task_graph_with_proposed_edges(proposal)
        require_unchanged_parent_completion_policy(proposal, parent)

        require_child_allocations_plus_integration_within_remaining_budget(proposal)
        children = publish_child_contracts_idempotently(proposal)

Partial work is retained according to what it establishes: source artifacts remain candidate material, a witnessed counterexample may become scoped negative evidence, and a diagnostic trace remains an observation. Admission judges each separately. Later revocation of a required child claim propagates through evidence dependencies; a mere provenance link does not invalidate an independently confirmed parent. Task dependencies express prerequisites for work, while support-set edges express logical reliance.

Optional GitHub adapter at the outer boundary

Use issues and pull requests for human-visible task publication, externally contributed candidates, coarse milestones and reviewable results. Keep inner-loop attempts, budget reservations, device leases and evidence validity in the service. The pilot may run entirely through CLI/API; GitHub is neither mandatory nor the system of record. This prevents per-trial API latency, rate limits and mutable labels from controlling physical GPU ownership.

Map external repository/issue/PR identities to immutable domain IDs. Inbound delivery is at least once: deduplicate provider event IDs, verify sender authority and re-fetch the submitted commit before ingestion. Outbound updates use the existing outbox and reconciliation; GitHub downtime delays publication without stopping already authorized local experiments. Pin submissions and review decisions to exact source commits. A task claim allocates contributor attention; it never grants a GPU lease. Choir's comment-based task lease is useful coordination precedent, not a substitute for runner fencing. [R26]

Evaluator code, policy, trusted workflow definitions and credentials must be outside the contributor's mutation authority. Enforce allowed paths and trusted evaluator identity in the service; do not rely on prompts asking an agent to refuse policy changes. Choir's inspected merge wrapper documents that status-name/conclusion checking alone cannot detect a workflow replaced with a green stub. Our acceptance decision must bind actual trusted evaluator identity and receipts, even when a GitHub check reports success. [R25]

Contributors may use separate model accounts, but their participation does not make total compute free. Record contributor-declared exploratory costs separately from service-metered qualification costs, mark unknown costs unknown, and retain the campaign's hard limits for all project-funded execution. Local prototype workers do not require shared credentials or repository write access.

05 · Experiment lifecycle and agent roles

The planner decomposes work into independent hypotheses: fusion, memory layout, launch geometry, precision-preserving algebra and algorithm changes. A proposer owns one bounded candidate; a critic seeks failure modes and requests checks. An evidence auditor checks receipt completeness and scope. An advisor can change search allocation, but cannot relax tolerances, edit the sealed evaluator, increase budget or waive a failed gate.

Briefings include relevant valid claims, their scope and epoch, rejected attempts with structured reasons, and unresolved hypotheses. Scratch notes and literature summaries remain explicitly unaccepted. Retrieval must filter invalid facts before summarization; a cached summary includes its source IDs and epoch and is refreshed when those dependencies change.

Long jobs are asynchronous: the workflow records a job and yields, while an event consumer resumes it when the persisted domain state changes. A missed callback is reconciled by querying jobs. Human interrupts happen before acquiring resources. Code before a resumed interrupt can run again; external effects therefore need domain-level idempotency even when graph checkpoints exist. [R5]

Stop on exhausted authorization, a satisfied target, a declared plateau, invalid baseline, or required operator intervention. “No improvement found” is a valid result. A successful run creates a reviewable candidate patch and report; it never merges that patch into a product automatically.

06 · Domain model and immutable evidence

Use relational tables for identities and projections, JSON Schema-validated manifests for domain payloads, and an append-only event log for state changes. Every record carries project_id, schema version and provenance. A workflow DAG answers “what runs next?”; the evidence DAG answers “what still supports this assertion?” Neither graph substitutes for the other.

Claim vocabulary

Use typed assertions such as numerical_contract_passed, sanitizer_suite_passed, latency_target_confirmed and expert_review_completed. These are different predicates, not levels in a universal confidence ladder. Reserve formally_verified for a real proof artifact checked by a named proof checker. LLM agreement never creates that predicate.

A numerical claim says “candidate C passed suite S, contract D, evaluator V and environment E.” A performance claim additionally names baseline B, measurement scope M, sampling plan P and uncertainty. It cannot imply correctness outside the tested domain or speed on a different GPU.

Canonicalize manifests with a specified JSON canonicalization scheme and UTF-8 encoding; reject duplicate keys, non-finite JSON numbers and ambiguous units. Use integer counts and explicitly unit-tagged decimal strings where exact identity matters. Hash the schema version, full scope, all supporting artifact references, source provenance, policy and environment. Never hash an unstable filesystem path as identity. Artifacts are uploaded to a temporary key, hashed, durably finalized, then registered in a transaction. An admission transaction references only finalized artifacts. Garbage collection follows a retention policy and cannot remove reachable accepted evidence; any emergency removal must mark affected claims unavailable before deleting bytes. 07 · Admission, invalidation and scheduling algorithms

Admission and revocation serialize on the same boundary

For the pilot, use one PostgreSQL transaction-scoped advisory lock per project for every dependency mutation, promotion and revocation. This deliberately favors simple correctness over write throughput. Acquire it before reading the current graph; use fresh READ COMMITTED statements inside the lock, or a correctly retried SERIALIZABLE transaction. Never reuse a pre-lock snapshot. Unique constraints enforce idempotency; unauthorized writers have no direct table mutation capability. PostgreSQL serialization failures require retrying the whole transaction. [R16]

def admit(proposal, actor):
    require_capability(actor, "claim:admit")
    with transaction():
        lock_project(proposal.project_id)
        prior = lookup_idempotency(proposal.key)
        if prior: return same_spec_or_conflict(prior, proposal)
        policy = load_frozen_policy(proposal.policy_hash)
        validate_schema_scope_and_authentic_receipts(proposal, policy)
        require_finalized_artifacts(proposal)
        require_no_cross_project_edges(proposal)  # v1 boundary
        require_acyclic_required_dependencies(proposal)
        for support in proposal.support_sets:
            require_all_members_current_and_scope_compatible(support)
            require_policy_sufficient(support, policy)
        event = append_event("claim_admitted", proposal)
        update_projection_and_epoch(event)
        insert_outbox("claim_status_changed", event)
    return event.receipt

def revoke(evidence_or_claim_id, reason, actor):
    require_capability(actor, "evidence:revoke")
    with transaction():
        lock_project(project_of(evidence_or_claim_id))
        append_revocation(evidence_or_claim_id, reason)
        impacted = reverse_required_dependency_closure(evidence_or_claim_id)
        for node in topological_order(impacted):
            # A support set is active iff all required members are active.
            # A claim is supported iff at least one sufficient set is active.
            recompute_current_validity(node)
        bump_project_epoch()
        enqueue_invalidations_and_workflow_wakeups(impacted)
    # Append evidence/revision to requalify later; never edit old observations.

Explicit claim revocation overrides its support sets until a new authorized revision is admitted. A descendant loses support only through required edges; “inspired by” and “derived source from” provenance edges do not automatically make an independently measured result false. Large closures are bounded in the pilot. If later moved to asynchronous recomputation, admission and retrieval must treat the affected scope as unavailable until recomputation completes; never expose stale projections as valid.

The queue uses per-campaign caps and age-based fairness, with priority classes for health checks, confirmation and exploration. No unbounded model-created priority. CPU compilation and proposal generation may overlap; clean timing reserves the whole physical GPU and a declared host resource envelope. [R12][R17]

A lease carries a monotonically increasing generation and runner boot identity. The runner rejects stale commands and tracks the active attempt in a durable local journal. Coordinator failover may reconcile the same attempt but may not start a replacement merely because a timeout expired. A lease fences the protocol; it cannot stop an already-running device kernel by itself.

Observed stateRequired actionForbidden inference
Submitted, acknowledgement lostQuery runner journal by attempt ID; resend identical request only under idempotent protocol.“No reply means it never started.”
Coordinator restartedReconcile ledger jobs, outbox, inbox and runner journal before resume.“LangGraph will recover all external effects.”

Retry only classified transient infrastructure failures, with bounded attempts and backoff. Deterministic compile failures and correctness failures become negative evidence. Each actual retry has a new attempt ID under the original operation; a deliberate additional measurement has a new operation ID. Do not reuse an old timing receipt as a fresh observation.

08 · GPU contract, checker qualification and measurement

Freeze the experiment before search

The campaign contract defines operation semantics, shapes, strides, alignment, dtypes, output layout, aliasing, permitted mutation, determinism, NaN/Inf behavior, allowed approximation, absolute/relative/ULP error policy, and supported devices. Tolerances are operation-specific and justified against a reference/error analysis. Changing accumulation order may be legal; silently lowering precision is not legal unless the contract permits it.

Baseline identity includes source and dependencies, compiler flags, math/TF32 policy, autotuning allowance, eager versus compiled mode, CUDA graph use and allocation behavior. Compare against the intended deployment baseline with comparable optimization opportunity. Report kernel-only and application-level effects separately; a faster isolated kernel can lose after launch, conversion or memory costs.

Stage compilation in a resource-limited environment. Start with a narrow CUDA entry-point ABI: typed buffer descriptors, dimensions and predeclared launches. Triton support must define an equally narrow trusted launcher boundary. Arbitrary candidate Python must not run in the timing controller, where it could monkey-patch timers, references or global state. Executing generated code in a container does not make the host GPU driver a security boundary; use a dedicated runner host or suitable VM, no secrets, bounded disk/CPU/memory and no candidate network. The initial threat model covers faulty and benchmark-gaming generated code, not safe hostile multi-tenancy against GPU-driver exploits.

Clean timing protocol

CUDA launches are asynchronous. Use a trusted timing controller and CUDA events for device work, or explicitly synchronized host measurement for end-to-end scope. Record which is used. Warm up compilation, autotuning, caches and clocks separately, then measure the frozen executable. Reset mutable inputs for every relevant run. Triton autotuning can rerun kernels and mutate inputs; its reset/restore hooks are a useful implementation reference. [R19][R20][R21]

Do not collect headline timing under a profiler or sanitizer. Nsight Compute replay can change execution and serialize work; profiling runs are separate diagnostic evidence. Capture temperature, clocks, power, utilization, host load and a fixed control kernel before/after measurement blocks. A drift threshold, established during calibration and frozen in policy, determines whether the entire affected block is rejected. Do not selectively discard slow candidate runs. [R22]

def confirm(finalists, frozen_policy, sealed_manifest):
    assert checker_qualification_current()
    assert finalists_frozen_before_opening_holdout()
    blocks = []
    for session in frozen_policy.independent_sessions:
        reserve_exclusive_gpu_and_host_envelope()
        attest_environment_and_run_health_control()
        for block in predeclared_blocks(session):
            seed = sealed_manifest.seed_for(block)
            order = randomized_balanced_order(seed)  # e.g. ABBA / BAAB
            baseline, candidate = run_reset_inputs_in_order(order)
            blocks.append(raw_samples_and_control_telemetry())
        release_only_after_terminal_receipt()
    require_predeclared_number_of_valid_blocks_or_return_inconclusive()
    # Sample independent blocks/sessions, not thousands of correlated events.
    estimates = analyze_predeclared_metrics(blocks, frozen_policy)
    return typed_confirmation_evidence(estimates, all_raw_artifacts)

Statistics: use paired log latency ratios for the declared workload and retain per-case results. A geometric mean is a useful summary, not a substitute for actual production throughput or critical-case latency. Estimate uncertainty by resampling independent blocks/sessions with pairing preserved; do not treat repeated events in one hot loop as independent experiments. Calibrate block count and duration against observed noise and the minimum effect of interest before the campaign.

Discovery is adaptive and descriptive. Confirmation uses fresh held-out inputs, predeclared sample size, fixed finalists and a finite hypothesis budget. Allocate a family-wise error budget across all finalist/metric/case decisions, for example Bonferroni allocation over the declared family. A bootstrap interval is an approximation whose coverage must be validated in calibration; use a more suitable prespecified method if it fails. Do not repeatedly peek and stop on a favorable interval. Repeated confirmation attempts consume the same declared family budget and fresh holdouts; once exhausted, report failure/inconclusive or start a newly reviewed campaign without erasing prior attempts.

Proposed pilot promotion rule: adjusted lower confidence bound for the primary speedup ≥ 1.05; every protected-case lower bound ≥ 0.98; declared memory cap met; numerical and sanitizer gates current; no invalid control blocks concealed. These thresholds are illustrative policy defaults to validate in S00/S02, not measured results. Insufficient precision yields inconclusive, never a fabricated win. Hardware/compiler changes require requalification according to compatibility rules; an old claim retains its historical scope.

Worked dependency failure — synthetic example

Candidate C passes checker V and confirms a speedup against B. Later a witnessed stale-output mutant reveals that V misses repeated-input cheating. Revoke V’s qualification; invalidate C’s numerical claim and any performance claim requiring it. Keep the raw timing observation, but remove C from current recommendations. A fresh checker V2 requires new numerical evidence and, when affected semantics or policy demand it, new timing confirmation. A second measurement using V is not independent support.

09 · Operations, budgets and reproducibility

Budget as an admission constraint

Track tokens by model and role, model-call count, compile CPU-seconds, exclusive GPU-seconds, stored bytes and wall-clock deadline. Price snapshots are separate dated accounting inputs. Never bake current provider prices into correctness logic. Reserve conservative maximum usage before dispatch, including bounded retries; settle measured usage afterward. In-flight and uncertain attempts retain reservations. Provider billing may differ from estimates, so any hard monetary promise requires verified provider limits and explicit margin.

Enforce token/output/time caps at the caller, subprocess and scheduler boundaries. Agent-spawned work inherits the campaign account. Exhaustion stops new work and permits only a bounded authorized cleanup/reconciliation allowance. A cost report includes failed candidates, tuning, critics, confirmation and infrastructure overhead; displaying only successful-run cost is misleading.

These are acceptance targets to test, not availability guarantees. Backups must capture a consistent artifact inventory; a database restored without required blobs cannot produce accepted current claims. Local durable acknowledgement protects a process crash, while disaster recovery can lose up to the stated backup window. Keep runner journals long enough to reconcile that window, and block automatic restart of ambiguous work.

Retain accepted-result artifacts and their transitive support for the life of the claim plus an agreed archival period. Failed-attempt bulky artifacts may expire by quota, but retain metadata, outcome and hashes; label expired evidence as unavailable. Redact secrets and user data before report export. Logs, prompts, candidate code and datasets have explicit access scopes and retention classes.

Migration and compatibility

Version domain schemas, workflow definitions, adapter contracts and evaluator policies separately. Pin running campaigns to compatible versions. Use additive database migrations with rollback/restore rehearsal; stop new admissions during incompatible upgrades. A workflow code upgrade must not resume old checkpoints blindly. Support replay into a versioned workflow or explicitly terminate and create a new campaign revision. Report readers must render older evidence without silently changing its interpretation.

Use fast pure-domain tests and fake runners on developer machines, then a small dedicated GPU suite. Never rerun already clean expensive campaigns without a changed binary, evaluator, policy, environment or unresolved concern. Record which dependency changed and which evidence it invalidates. Independent test authors receive the approved contract, interfaces and expected user workflow before implementation details. Keep their original tests and failures. If an oracle defect is discovered, revoke affected qualification and re-establish it; never silently weaken tests to make a candidate pass. Controlled usefulness study

Compare equal-budget strategies over a prespecified workload set spanning operation families and difficulty. Randomize task/seed assignment and execution order; block on hardware and environment. Count invalid kernels, timeouts, no-improvement tasks and budget exhaustion in the denominator. Primary outcomes are independently confirmed improvement and total cost/time to reach it. Secondary outcomes include regression rate, operator interventions and invalidation recovery time. Separate search-quality gains from parallel wall-clock gains and extra compute.

Stage rollout from fake-runner development to attended dedicated-host experiments, bounded unattended pilot, then approved product integration. Kill switches stop new admission/dispatch while allowing receipt reconciliation and owned-job cleanup. Rollback can disable a workflow version without deleting evidence. A missing owner, unqualified checker, unstable baseline, unexplained drift, broken isolation or unreconciled job is a concrete stop condition for the affected lane.

Generalization rule: the system transfers well to tasks with a reproducible artifact, bounded execution environment, meaningful oracle and explicit acceptance policy: CPU algorithm tuning, compiler flags, numerical solvers, database query plans and selected simulation experiments.
